0x01 附件分析

项目结构:

从 docker-entrypoint.sh 可知 flag 的存放位置与权限:

即 flag 在容器根目录 /flag,而服务是一个暴露到公网的 Vite dev server(npm 跑的是 vite,不是构建后的静态产物)。

vite.config.js 的 fs 防护配置值得注意:

server.fs 是 Vite dev server 防止任意文件读取的机制:allow 限制可以访问哪些目录,deny 追加禁止列表。/flag 在 / 下,不在 allow 内,理论上被拦。

robots.txt 中 Disallow: /@fs/ 是个提示:@fs/ 前缀是 Vite 暴露原始文件系统的方式,但直接访问仍会受 server.fs.allow 限制。

页面本身连接 ws://127.0.0.1:8081 展示「三角洲行动」玩家坐标,README 也说明与解题无关,纯粹迷惑项。

0x02 漏洞发现

版本匹配 CVE: 附件 package.json 锁定 vite: 6.4.1。该版本正好落在 CVE-2026-39363 的受影响区间:

  • Vite 6:>= 6.0.0, <= 6.4.1(6.4.2 修复)
  • 本质:Vite 的 HMR WebSocket(Sec-WebSocket-Protocol: vite-hmr)没有执行 server.fs.allow 校验,可调用服务端 fetchModule 方法传入 file:// URL,实现任意文件读取。

确认 HTTP 路径被封,但这也印证了 /flag 真实存在且容器根目录为 /app。
